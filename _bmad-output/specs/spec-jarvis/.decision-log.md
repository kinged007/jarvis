## 2026-06-02 — Revision 1: Resolved open questions

**User decisions:**
1. TTS/STT: Deepgram for both. STT only after wake word (not constant — cost concern).
2. Wake word: Lightweight browser-side Porcupine detector. Full utterance capture from detection moment (Alexa-style).
3. Mid-execution commentary: Dedicated TTS tool. Agent behavior in SOUL.md/AGENTS.md.
4. BFF location: BFF, client static files, and Hermes CLI all colocated on same machine. User accesses remotely.
5. Weather: Frontend-only widget, fetches directly from API.
6. Widgets: Phase 2 deferred (script-driven with DSL). Phase 1: weather + system status only.

**Changes applied:**
- SPEC.md: CAP-2, CAP-5, CAP-15, CAP-16 updated. Constraints, assumptions, and resolved decisions sections rewritten.
- stack.md: Rewritten with Deepgram, Porcupine wake word, colocated deployment.
- voice-interaction-model.md: Rewritten with Porcupine wake word flow, Deepgram STT/TTS pipeline, audio buffer for continuous capture.
- widget-system.md: Rewritten with Phase 1/2 split, DSL schema for Phase 2, weather as frontend-only widget.

**Verdict:** All open questions resolved. Spec now reflects final decisions. Ready for architecture phase.
