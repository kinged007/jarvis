## 2026-06-06: ONNX runtime WASM loading under Vite

**Problem:** openWakeWord depends on onnxruntime-web@1.24.1 (transitive).
At runtime, the ONNX backend does `import(wasmPaths + "ort-wasm-simd-threaded.jsep.mjs")`,
which Vite intercepts in dev. Vite's transformMiddleware refuses to serve
`/public/*` files as JS modules (treats them as static assets) and returns
500. The `.mjs` file is mandatory because it does `new URL("...jsep.wasm",
import.meta.url)` to locate the binary.

**Tried and rejected:**
- `optimizeDeps.exclude: ["onnxruntime-web", "openwakeword-js"]` — excludes
  pre-bundling but doesn't change dev-time request handling; the 500 persists.
- `resolveId` hook marking the import external — only affects bundling, not
  the runtime dev request Vite intercepts.
- `?import` suffix (added by Vite when it sees an ESM import) was the exact
  trigger for the 500. Without `?import`, `/public` files serve fine.
- `vite-plugin-static-copy` — moves files but doesn't change Vite's refusal
  to serve /public as a module.

**Adopted:** Custom Vite plugin at `packages/client/vite/plugins/onnx-wasm-public.ts`
that runs a middleware ahead of `transformMiddleware` for any URL starting
with `/models/`. It:
1. Strips the prefix + query string.
2. Reads the file from `packages/client/public/models/` (resolved via
   `import.meta.url` so it works regardless of where Vite is launched).
3. Sets the right Content-Type (`text/javascript` for `.mjs`,
   `application/wasm` for `.wasm`, `application/octet-stream` for `.onnx`).
4. Calls `res.end(content)` so `transformMiddleware` never sees the request.

**Why this works:** Vite 8 invokes `configureServer` BEFORE adding its
own `transformMiddleware` and `servePublicMiddleware`. Anything we end
here short-circuits the chain (no `next()` call). Plain `.mjs` requests
also work because both code paths are intercepted identically.

**Also required (independent fixes):**
1. `vite.config.ts` needs `envDir: path.resolve(__dirname, "../..")` so
   Vite reads the same workspace-root `.env` the BFF reads. Without
   this, `VITE_OPENWAKEWORD_ENABLED` is undefined and the service is
   silently inert.
2. `wasmPaths` must end with a trailing slash. ONNX does
   `wasmPaths + filename` as raw string concat — `"models" + "ort-..."`
   = `"modelsort-..."` (404). Use `${MODEL_PATH_BASE}/`.
3. `ort-wasm-simd-threaded.jsep.mjs` must be in `/public/models/`. The
   .mjs is a JS loader that the .wasm binary is loaded AS a module from.
   `postinstall` script (`packages/client/scripts/copy-onnx-runtime.mjs`)
   keeps it in sync with the installed onnxruntime-web version and
   removes stale variants (asyncify, jspi, basic) that aren't needed
   by the openWakeWord jsep build.

**Bugs hit during integration:**
- Duplicate `plugins:` key in `vite.config.ts` — second key overrides
  first (Object.assign behavior), so `onnxWasmPublic()` was never
  registered. Merged into a single array.
- Wrong `__dirname` resolution in the plugin — `import.meta.url` for
  `packages/client/vite/plugins/onnx-wasm-public.ts` is
  `.../packages/client/vite/plugins/`, so `../public/models/` resolved
  to `.../packages/client/vite/public/models/` (wrong). Fixed with
  `resolve(__dirname, "../..", "public/models")`.

## 2026-06-06: Switched to `openwakeword-wasm-browser`

**Problem (recap):** After all the openwakeword-js fixes
(proxy-worker hang → Web Worker rewrite; COEP→CORP) the browser
still fired `Worker.onerror` with an empty `e.message`. Diagnosis
showed the worker script was being served correctly with CORP, but
the minified `worker.mjs` bundle from `openwakeword-js@0.1.27`
itself wouldn't initialize in a module-worker context under Vite.
Root cause is opaque (the bundle is minified) and the upstream
package is a thin wrapper around onnxruntime-web that doesn't add
much over using ORT directly.

**Replaced with:** `openwakeword-wasm-browser` v0.1.0 (David Navarro,
https://github.com/dnavarrom/openwakeword_wasm). A purpose-built,
browser-first wrapper around onnxruntime-web + the openWakeWord
ONNX models. Runs entirely on the main thread with an
AudioWorklet — no separate Worker, no module-worker gotchas.

**Architecture:**
1. WakeWordEngine creates an `AudioContext` + `AudioWorklet` for
   mic capture. The worklet (defined inline as a string, registered
   via `audioContext.audioWorklet.addModule(blobURL)`) emits 1280-
   sample Float32Array chunks (80ms @ 16kHz) via `port.postMessage`.
2. Main thread runs the 3-stage ORT pipeline per chunk:
   - melspectrogram (`melspectrogram.onnx`, `[1, 1280]` → 5×32 mel frames)
   - mel → /10 + 2 transform (per the openWakeWord training spec)
   - embedding (`embedding_model.onnx`, `[1, 76, 32, 1]` → 96-dim)
   - keyword model (e.g. `hey_jarvis_v0.1.onnx`, `[1, 16, 96]` → score)
3. VAD (`silero_vad.onnx`) gates detections with a 12-frame hangover
   (1s after VAD drops below 0.5) so the keyword score has time to
   peak on the trailing audio.
4. `score > threshold && vadActive && !cooldown` → emit `detect` event
   with `{ keyword, score, at }`.

**Where the JARVIS-specific bits live:**
- Pre-roll ring buffer (configurable seconds of audio captured before
  detection) — filled from a SEPARATE mic stream we open (the
  engine owns the wakeword mic; we open a sibling stream for the
  STT-bound audio).
- VAD-driven command capture: same RMS-based silence detection
  shared with the STT service. When the engine emits `detect`, we
  snapshot the pre-roll buffer, start accumulating post-wake audio,
  fire `onWake` listeners, and ship the combined pre-roll + command
  audio to the BFF after `VITE_WAKEWORD_SILENCE_MS` of silence.
- `App.tsx` already cancels in-flight agent runs + TTS on wake.

**Asset layout:**
- `public/openwakeword/models/` — 4 ONNX models (melspectrogram,
  embedding, silero_vad, hey_jarvis_v0.1) + 5 extras for other
  keywords. Staged from the `openwakeword-wasm-browser` package's
  own `models/` folder.
- `public/openwakeword/ort/` — `ort-wasm-simd-threaded.{mjs,wasm}`
  (the non-jsep variant; we use `executionProviders: ['wasm']` only).
  Self-hosted because COEP=require-corp blocks the default ORT CDN.

**Vite plugin (`vite/plugins/onnx-wasm-public.ts`):** serves files
from `public/openwakeword/*` at `/openwakeword/*` with the right
Content-Type (text/javascript for .mjs, application/wasm for .wasm,
application/octet-stream for .onnx) and
`Cross-Origin-Resource-Policy: same-origin`. Has both
`configureServer` and `configurePreviewServer` hooks so production
builds work the same as dev.

**Env vars:**
- `VITE_WAKEWORD_BASE_URL` (default `/openwakeword/models`) — where
  the .onnx files live. Passed to the engine as `baseAssetUrl`.
- `VITE_WAKEWORD_ORT_PATH` (default `/openwakeword/ort/`) — where
  ORT loads its WASM from. Passed to the engine as `ortWasmPath`.
- `VITE_WAKEWORD_MODEL` (default `hey_jarvis`) — keyword name,
  one of MODEL_FILE_MAP keys.
- `VITE_WAKEWORD_THRESHOLD` (default `0.5`) — score required to
  emit `detect`, on top of the engine's VAD + cooldown gating.

**Threshold rationale:** The engine emits `detect` only when
`score > threshold && vadActive && !cooldown`. 0.5 is the
`openwakeword-wasm-browser` default and the right starting point
for the bundled pre-trained `hey_jarvis` model. The previous
0.09-from-openwakeword-js reasoning doesn't apply here — that
library surfaced *raw* openWakeWord scores; this engine layers VAD
+ cooldown on top of the same raw scores, and the empirical sweet
spot for "few false positives, real wakeword still triggers" is
around 0.5. Tunable via env.

**Audio processing flags:** Both mics (the engine's wakeword mic
and our command mic) pass `echoCancellation: false,
noiseSuppression: false, autoGainControl: false` to
`getUserMedia`. The engine's bundled example does the same.

**Dependencies:** Removed `openwakeword-js` from
`packages/client/package.json` (added `openwakeword-wasm-browser`
as a `file:` reference to the .tgz vendored at
`packages/client/vendor/openwakeword-wasm-browser-0.1.0.tgz`).
Removed `optimizeDeps.exclude: ["onnxruntime-web", "openwakeword-js"]`
from `vite.config.ts` — the pre-bundling path is fine now that ORT
loads its wasm from a self-hosted path the plugin serves correctly.

**What was reverted:**
- Removed the `worker.mjs` copy step from the postinstall script.
- Removed the `/models/*` handler from the Vite plugin.
- Removed the old `public/models/` directory (orphan from the
  openwakeword-js era).
- Reverted the SPEC changes that referenced the Worker pattern.


## 2026-06-06: Toggle logic + indicator visibility

**Problem:** Clicking the wakeword indicator for the first time was
a no-op because the toggle callback keyed off `userDisabled`, which
starts at `false` (i.e. the user hadn't disabled anything). The
indicator also only showed an icon — a green dot is ambiguous when
the service is in 4 different states (listening / idle / off /
error).

**Adopted:** Toggle callback now keys off
`wakewordService.getState().listening` — first click always starts.
Indicator (`WakeWordIndicator.tsx`) now always renders a visible
text label (`WAKEWORD: LISTENING` / `IDLE` / `OFF` /
`ERROR — {msg}`) next to the icon, with distinct icons (Ear / Mic /
MicOff / AlertCircle) and a `title` attribute for hover tooltip.
Aria-label set so screen readers get the same context.
